# Feature Notes — additions to the backlog

Recorded 2025-09-16, from product owner request. These extend the PRD
(`0.E-Ink Mode.md`); nothing here supersedes it.

## 1. Menu bar icon with editable settings

**Want:** edit E-Ink Mode settings directly from the little menu bar icon (the
`◐` tray icon, PRD §15) — not a separate preferences window.

**Clarified intent:** the dropdown *is* the settings UI. Toggles, brightness,
schedule times all changeable in place.

**Relates to:** PRD §15 (User Interface), §9.6 (config persistence — edits must
write through to the config file so the CLI and scheduler see the same values).

**Acceptance sketch:**
- Click icon → menu shows current live state (mode on/off, brightness, schedule)
- Change any setting → takes effect immediately, persists to config
- One-click toggle stays the primary action (never bury it)

**Status:** menu bar app is Prototype 1/2 territory per PRD §28. Prototype 0 CLI
is unaffected.

## 2. Manual grayscale toggle ("smart grayscale")

**Want:** enable/disable the grayscale part of E-Ink Mode directly from the menu
bar icon.

**Note on naming:** owner calls this "smart grayscale". Don't confuse with
macOS *Smart Invert* (separate feature, `EINK_INVERT` in prototype 0).
Confirm final naming before shipping.

**Acceptance sketch:**
- Grayscale can be toggled independently of brightness/dock settings
- Toggling grayscale off does not exit E-Ink Mode or discard captured state
- PRD §21 still applies: pre-existing grayscale is restored, not cleared

## 3. Scheduled activation — grayscale by 21:00 nightly

**Want:** E-Ink Mode (at minimum grayscale) turns **itself on at 21:00** every
night. Owner: *"I think I should be in grayscale mode by 9 o'clock every night."*

**Defaults to start with:**

| | |
|---|---|
| On | 21:00 daily |
| Off | 07:00 daily (owner to tune; sunset→sunrise is the PRD §14 long-term version) |

**Requirements:**
- Schedule calls the same `eink on` / `eink off` entry points as the manual
  toggle — one state machine, not two
- Idempotent: 21:00 fires while already on → no-op (no double state capture)
- Missed-run catch-up enabled (machine asleep/off at 21:00 → runs on wake)
- Schedule editable from the menu bar icon (feature 1)

**Relates to:** PRD §14 (Scheduling), which already sketches 10 PM–2 AM; owner
preference is **21:00**.

**Status:** will be delivered by the app's scheduler on macOS. Interim option if
wanted before the app exists: two launchd jobs calling `prototype0/eink`.

## 4. Windows parity

Owner is setting up the same automation on a Windows PC. Handoff brief for the
Windows agent written to `2.Windows Handoff.md` — it carries over the
principles that worked in prototype 0 plus verified Windows mechanisms
(color filter registry/hotkey, WMI brightness, taskbar autohide, Task
Scheduler).
